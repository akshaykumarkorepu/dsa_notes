
# Valid Parenthesis String (`(`, `)`, `*`) — Greedy Interview Notes

---

# NOTE

## PROBLEM:

Given a string `s` containing only `'('`, `')'`, and `'*'`, determine whether it can be made into a valid parenthesis string.

Rules:

- Every `'('` must have a matching `')'`.
- Every `')'` must have a matching `'('`.
- `'('` must appear before its matching `')'`.
- `'*'` can represent:
  - `'('`
  - `')'`
  - `""` (empty string)

---

# PATTERN:

**Greedy Range Tracking (Bounds Greedy)**

Instead of tracking every possible balance of unmatched `'('`, maintain only the **minimum** and **maximum** possible balance after processing each character.

---

# WHY THIS PATTERN:

Each `'*'` introduces **three possibilities**, causing brute force to branch exponentially.

However, the only state that matters is:

> **How many unmatched '(' could we possibly have after processing this prefix?**

Instead of storing every possible balance individually, we observe that all possible balances always form a **continuous interval**.

So we only store:

- `low` → Minimum possible unmatched `'('`
- `high` → Maximum possible unmatched `'('`

This compresses exponentially many states into just **two integers**.

---

# CORE IDEA:

Brute force explores every interpretation of `'*'`.

Greedy **does not decide immediately** what a `'*'` represents.

Instead, it keeps **all possibilities alive simultaneously** by maintaining the interval:

```text
[low, high]
```

Example:

Instead of remembering

```text
0
1
2
3
```

remember only

```text
low = 0
high = 3
```

Every possible balance lies inside this interval.

---

# GREEDY OBSERVATION:

Brute force differs only in the **balance** (number of unmatched `'('`).

Instead of storing every balance separately:

Store only

```text
Minimum possible balance
Maximum possible balance
```

and update this interval after processing every character.

---

# WHY GREEDY WORKS:

At every prefix,

```text
[low, high]
```

contains **every feasible unmatched '(' balance**.

Since all possible balances always form a continuous interval, knowing only the endpoints is sufficient.

We never lose any valid interpretation.

---

# GREEDY CHOICE:

Never immediately assign a meaning to `'*'`.

Instead,

update the range of all possible balances.

---

# WHY THIS CHOICE IS SAFE:

Suppose after processing some prefix the possible balances are

```text
2
3
4
5
```

Instead of storing all four values,

store only

```text
low = 2
high = 5
```

Nothing is lost because every balance between them is also achievable.

Therefore tracking only the endpoints preserves all possibilities.

---

# SORTING:

**Not Required**

The characters must be processed in their original order.

This is a single left-to-right scan.

---

# INVARIANT:

After processing every prefix,

```text
[low, high]
```

represents **every possible unmatched '(' balance** after processing that prefix.

This property remains true throughout the algorithm.

---

# BRUTE FORCE:

## Intuition

For every `'*'`, recursively try:

- `'('`
- `')'`
- `""`

If any interpretation forms a valid string,

return `true`.

---

## Recursive State

```cpp
solve(index, balance)
```

where

- `index` = current character
- `balance` = unmatched `'('`

---

## Base Cases

### Invalid

```cpp
balance < 0
```

More closing brackets than opening brackets.

Return `false`.

---

### End of String

```cpp
index == n
```

Return

```cpp
balance == 0
```

because every `'('` must be matched.

---

## Brute Force Code

```cpp
class Solution {
public:

    bool solve(int index, int balance, string &s)
    {
        if(balance < 0)
            return false;

        if(index == s.size())
            return balance == 0;

        if(s[index] == '(')
            return solve(index + 1, balance + 1, s);

        if(s[index] == ')')
            return solve(index + 1, balance - 1, s);

        return solve(index + 1, balance + 1, s) ||
               solve(index + 1, balance - 1, s) ||
               solve(index + 1, balance, s);
    }

    bool checkValidString(string s)
    {
        return solve(0, 0, s);
    }
};
```

Each `'*'` creates **3 recursive branches**.

With multiple stars:

```text

Number of recursive calls grows exponentially.

---

## Complexity

**Time:** `O(3^n)`

Reason:

Every `'*'` creates three recursive branches.

---

**Space:** `O(n)`

Reason:

Maximum recursion depth equals the string length.

# TRANSITION FROM BRUTE FORCE TO GREEDY

Brute force explores every possible balance.

Example:

```text
0
1
2
3
4
```

Observe:

The balances are always **continuous**.

Instead of storing every balance,

store only

```text
low = minimum balance
high = maximum balance
```

This compresses exponentially many states into two numbers.

---

# OPTIMAL APPROACH

Maintain:

```cpp
low
```

Minimum possible unmatched `'('`

and

```cpp
high
```

Maximum possible unmatched `'('`

Update them while scanning the string once.

---

# HOW THE RULES ARE DERIVED

## If character is '('

Every balance increases.

```cpp
low++;
high++;
```

---

## If character is ')'

Every balance decreases.

```cpp
low--;
high--;
```

---

## If character is '*'

Smallest balance:

Treat it as `')'`

```cpp
low--;
```

Largest balance:

Treat it as `'('`

```cpp
high++;
```

So

```cpp
low--;
high++;
```

---

## Why

```cpp
low = max(low,0);
```

Negative unmatched `'('` is impossible.

If `low` becomes negative,

those interpretations simply do not exist.

Clamp it to zero.

---

## Why

```cpp
if(high < 0)
    return false;
```

Even the **largest possible balance** is negative.

That means

Every interpretation has more `')'` than `'('`.

No future character can repair an invalid prefix.

Immediately return `false`.

---

## Final Check

```cpp
return low == 0;
```

If balance `0` is still inside the interval,

there exists at least one valid interpretation.

---

# ALGORITHM

1. Initialize

```cpp
low = 0
high = 0
```

2. Traverse every character.

3. Update the interval:

- `'('`

```cpp
low++;
high++;
```

- `')'`

```cpp
low--;
high--;
```

- `'*'`

```cpp
low--;
high++;
```

4. Clamp

```cpp
low = max(low,0);
```

5. If

```cpp
high < 0
```

return `false`.

6. At the end,

return

```cpp
low == 0
```

# PATTERN RECOGNITION

Use **Greedy Range Tracking (Bounds Greedy)** when:

- One character can represent multiple possibilities.
- Brute force branches exponentially.
- The state can be represented as a **continuous interval**.
- Only the minimum and maximum possible state matter.
- A single left-to-right scan can maintain this interval.

---

# CLEAN C++ CODE

```cpp
class Solution {
public:
    bool checkValidString(string s) {

        // Minimum and maximum possible unmatched '('
        int low = 0, high = 0;

        for(char ch : s)
        {
            if(ch == '(')
            {
                // Every interpretation gains one unmatched '('
                low++;
                high++;
            }
            else if(ch == ')')
            {
                // Every interpretation loses one unmatched '('
                low--;
                high--;
            }
            else
            {
                // Minimum balance -> treat '*' as ')'
                low--;

                // Maximum balance -> treat '*' as '('
                high++;
            }

            // Negative unmatched '(' is impossible
            low = max(low, 0);

            // Even the best interpretation has failed
            if(high < 0)
                return false;
        }

        // If balance zero is still possible, answer is true
        return low == 0;
    }
};
```

---

# INTUITION BEHIND THE IMPORTANT LINES

### `low++; high++;`

Every interpretation gains one unmatched `'('`.

---

### `low--; high--;`

Every interpretation closes one unmatched `'('`.

---

### `low--; high++;`

A `'*'` could decrease or increase the balance, so update both ends of the interval.

---

### `low = max(low,0);`

Negative unmatched `'('` is impossible.

Clamp impossible balances.

---

### `if(high < 0)`

Even the largest possible balance is negative.

Every interpretation has already failed.

---

### `return low == 0`

If zero balance is still achievable,

there exists at least one valid interpretation.

---

# EASY INTERVIEW SUMMARY

> Brute force tries all three possibilities for every `'*'`, leading to `O(3^n)` complexity. The key insight is that we only care about the **range of possible unmatched '(' balances**, not every individual balance. Since these balances always form a continuous interval, we maintain only its endpoints: `low` (minimum possible balance) and `high` (maximum possible balance). We update this interval while scanning the string once, immediately return `false` if `high < 0`, and finally return `true` if `low == 0`, meaning a balance of zero is still achievable. This gives an optimal solution with **O(n)** time and **O(1)** space.
